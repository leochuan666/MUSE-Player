# Muse Player 设计文档

> 产品设计理念 · 交互特色 · 系统架构 · AI 流程详解

---

## 一、产品设计理念

### 1.1 核心洞察

大学生群体面临学业压力、就业焦虑、人际关系等多重情绪挑战。音乐是最便捷、最经济的情绪调节手段，但存在三个痛点：

1. **搜索门槛**: 用户需要知道"想听什么"才能搜，而情绪低落时恰恰缺乏这种主动性
2. **平台碎片化**: 版权分散在多个平台，用户需要反复切换搜索
3. **孤独感**: 传统播放器是"一个人听"，缺少轻量级的共听和表达空间

### 1.2 设计目标

- **降低搜索门槛**: 从"搜歌名"变成"说心情"
- **聚合多平台**: 一次搜索覆盖网易云、酷狗、QQ音乐、酷我
- **轻社交体验**: 弹幕让听歌从个人行为变成情绪空间

### 1.3 设计原则

| 原则 | 说明 |
|------|------|
| 零学习成本 | 像聊天一样输入心情，不需要学习任何操作 |
| 即时反馈 | 输入后立即显示 AI 正在理解，推荐卡片逐张出现 |
| 渐进式呈现 | 先给推荐理由和封面，用户决定是否播放 |
| 氛围优先 | 极光绿暗色主题 + 弹幕动画，营造沉浸情绪空间 |

## 二、视觉设计

### 2.1 设计语言

**极光绿像素复古未来主义 (Aurora Teal Pixel Futurism)**

- **主色**: `#40e0c0` (Aurora Teal) — 介于绿与青之间，传递冷静与希望
- **底色**: `#060f14` — 极深蓝黑，模拟深夜独处氛围
- **字体**: Consolas / Courier New (等宽像素字体)
- **氛围**: 扫描线 + 呼吸光晕 + 极低透明度渐变

### 2.2 布局（16:9 横屏优先）

```
┌──────────────────────────────────────────┐
│             Canvas 弹幕层 (z-index:2)      │
├─────────────────┬────────────────────────┤
│   左区 50%      │   右区 50%              │
│                 │                        │
│  歌单列表       │   Agent 对话区           │
│  像素时钟       │   用户输入 & AI 回复      │
│  播放控件       │   推荐卡片 (PLAY按钮)     │
│                 │                        │
├─────────────────┴────────────────────────┤
│   状态栏: 当前播放 · 平台标记 · 版本号      │
└──────────────────────────────────────────┘
```

### 2.3 弹幕系统

两层内容混合从右飘过：
- **主层**: 当前播放歌曲的歌词（较大字号、高透明度）
- **辅层**: 网友情绪故事/评论（较小字号、低透明度）
- 速度与密度由当前歌曲的 BPM 和情绪类型动态调节

## 三、交互设计

### 3.1 核心交互流

```
打开页面 → 设置 API Key (首次) → 输入心情文字
  → Agent 分析 → 多平台搜索 → 展示推荐卡片
  → 用户点击 PLAY → 加入播放列表 → 开始播放
  → 弹幕启动 → 自动预加载下一首 → 循环
```

### 3.2 推荐卡片交互

每张卡片包含：
- 歌单/歌曲名
- 歌手
- 音乐平台来源
- 风格标签
- 曲目数/时长
- **PLAY** 按钮（一键播放）
- 源不可用时灰显

### 3.3 播放控制

- 播放/暂停、上一首、下一首
- 音量滑块
- 进度条（可拖拽）
- 歌单列表点击切换
- 自动预加载：当前歌曲快结束时自动搜索下一批

## 四、AI 系统设计

### 4.1 模型

- **主模型**: DeepSeek V4 Flash (deepseek-chat)
- **能力**: 对话理解 + Web Search tool
- **调用方式**: REST API (`api.deepseek.com/v1/chat/completions`)

### 4.2 情绪分析流程

```
用户输入
  → System Prompt: "你是音乐情绪分析师..."
  → 解析输出 JSON:
     {
       mood: "忧郁",
       moodTags: ["雨天", "独处", "慢节奏"],
       searchKeywords: ["雨天咖啡馆", "深夜独处", "Lofi Jazz"],
       reply: "我懂这种感觉。雨天最适合..."
     }
  → searchKeywords → 多平台搜索
  → 搜索结果 → Agent 生成推荐卡片
```

### 4.3 Agent 提示工程

**System Prompt 核心要素**:
- 角色设定：音乐情绪分析师
- 输出格式：严格 JSON
- 搜索策略：优先中文歌曲，关注大学生群体偏好
- 推荐理由：个性化、有温度、不模板化
- 安全边界：不推荐暴力/色情/政治敏感内容

### 4.4 种子扩散机制

用户播放一首歌后，系统以该歌曲为"种子"：
1. 用种子歌曲的风格标签生成新的搜索关键词
2. 多平台搜索获取风格相似的歌曲
3. 自动预加载，实现连续播放

## 五、多平台音乐源架构

### 5.1 搜索优先级

```
网易云音乐 (localhost:3000)
  ↓ 失败
酷狗音乐 (localhost:9000)
  ↓ 失败
QQ音乐 (localhost:9000)
  ↓ 失败
酷我音乐 (localhost:9000)
  ↓ 失败
DeepSeek 联网搜索 (api.deepseek.com)
```

### 5.2 匹配分数机制

`matchScore(requested, result)` 函数：
- 清理括号内容、feat. 标记、多余空白
- 对比歌名和歌手名
- 低于 45 分的结果自动过滤
- 确保推荐相关性

### 5.3 音质回退

URL 解析支持音质自动降级：
- 优先请求 320kbps
- 失败自动回退 128kbps
- 确保在各种网络条件下都能播放

## 六、Demo Mode 设计

### 6.1 触发条件

- 自动检测：local API 2 秒内无响应
- 手动切换：设置面板中开启

### 6.2 Demo 数据

- 内置 30+ 条模拟歌曲数据
- 覆盖 8 种情绪类型
- 使用 CC0 免版权短音频样本
- 预置弹幕故事和模拟歌词

### 6.3 行为

- 搜索 → 返回匹配的模拟歌单
- 播放 → 使用内嵌/CC0 音频
- Agent → 使用预置回复模板（无需 API Key）
- 弹幕 → 使用预置数据

## 七、技术决策记录

| 决策 | 理由 |
|------|------|
| 单文件 HTML | 零部署门槛，评委双击即可打开 |
| Consolas 等宽字体 | 像素复古风格，所有系统内置 |
| Canvas 弹幕 | 性能优于 DOM 动画，支持高密度弹幕 |
| AbortController 超时 | 标准 Web API，无需第三方库 |
| localStorage | 纯前端存储，无隐私风险 |
| PWA | 可添加到桌面，离线可用 |
